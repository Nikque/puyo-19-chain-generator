# ぷよぷよ1〜19連鎖盤面ジェネレーター

[English README](README.en.md)

4色または5色を使い、空盤面から2個組で構築・発火する1〜19連鎖盤面を探索するC++20プログラムです。成功した盤面のURLを `19chain_urls.txt` に追記します。初期設定では、19連鎖・76個・4色の新しい盤面を100件生成します。

互換性のため、18連鎖以下も同じ名前のURLファイルへ保存します。

## Windows実行版（v0.2.1）

Releaseの `windows-x64.zip` を展開し、`run.cmd` を実行してください。exeの直接実行でも日本語を表示できます。コンソールが接続されている場合は実行中だけ出力文字コードをUTF-8にし、終了時に元へ戻します。ファイルへリダイレクトしたログもUTF-8です。進捗行はコンソール幅に合わせ、折り返しによる表示崩れを防ぎます。

Windowsの設定パスには日本語や絵文字も使えます。`run.cmd` はそのフォルダーへ移動して設定を読み、URLを保存します。引数なしのexeは作業フォルダーの `config.ini` を読みます。既存の設定は新しい版でも利用できます。URLファイルの最終行に改行がない場合も、次のURLを別の行に追記します。既存ファイルの読み込み失敗はエラーとして報告します。

CMakeはビルドのたびに `config.ini` と `run.cmd` を実行ファイルの隣へ同期します。ソースが変わらず設定だけを編集した場合にもコピーします。Windowsの追加テストでは、CP932で開始した実際のコンソールでexeとrun.cmdの日本語表示、文字コードの復元、進捗の折り返し防止を検査します。日本語・絵文字・UTF-8 BOM付き設定の読み込み、改行なし履歴への追記、重複除外、入出力エラーも検査します。

## 採用条件

- 6列×13段。13段目は連結・消去に参加せず、下のぷよが消えると落下します。
- 指定した連鎖数の各消去は、同時消しなしの単独4個消しです。
- 盤面の個数は `4 * target_chain + extra` です。`extra` は `min_extra_puyos` から `max_extra_puyos` の範囲で選びます。連鎖後には `extra` 個が残ります。
- 偶数個の盤面は直接積みます。奇数個は最初の3組で計画した5個消しを一度だけ行い、1個を残してから積みます。その後は最後の組だけが本体の連鎖を発火します。計画外の消去や3列目12段目の窒息を禁止します。
- 出現位置（左3列目の12段目が軸、13段目が子）から各配置までの左右移動・落下・回転・壁蹴り・床蹴り・クイックターンの経路を探索します。軸は14段目に入れず、13段目まで埋まった壁を越えられません。
- 横置きは高さの違う隣接列への「ちぎり」も扱います。最初の3手は合計3色以内とし、AC通の初手制限にも合わせます。
- 保存前に、出力する操作経路を空盤面から再生し、盤面一致・準備消去以外の途中の非発火・指定連鎖数を再検査します。
- 過去の `19chain_urls.txt` と今回の実行中の同じURLは除外します。

**保証範囲:** 通の配置・消去ルールに基づく離散的な操作モデルでの構築経路です。フレーム単位の自動落下、接地時間、入力受付時間、各機種の差はモデル化していません。出力は必要なツモと操作順であり、特定ゲームの乱数シード／配ぷよ列との照合は行いません。14段目へ子ぷよを固定する配置は探索対象から除外します（移動中に子ぷよが14段目を通ることはあります）。おじゃまぷよは扱いません。

77個の19連鎖も生成できます。例えば、空盤面へ `AA`, `AA`, `AB` の3組を置き、離れた縦2個ずつのAを3組目のAでつなぐと5個消しとなり、Bが1個残ります。以後38組を置けば、合計41組（82個）を使い、5個消去後の77個で19連鎖を発火できます。準備消去は本体の19連鎖には数えません。準備の3組と消去も出力手順と検証の対象です。

偶数個は `N/2` 手、奇数個は `(N+5)/2` 手です。余分なぷよの設定は**最終発火前の6×13盤面に残る個数**に対する値で、準備で消える5個を含みません。14段目へぷよを固定する配置は一切使いません。

## ビルドとテスト

Visual Studio 2022などのC++20コンパイラーとCMake 3.16以降を使います。

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
cd build/Release
.\random_19_chain.exe
```

Visual StudioのCMakeプロジェクトとして開くこともできます。ビルド時に `config.ini` を実行ファイルの隣へコピーします。上の `build/Release` はVisual Studioジェネレーターの例です。性能測定は必ず **Release** で行ってください。

`generator_regressions` は13段の壁で左右の端へ到達できないこと、12段の壁はクイックターンで越えられること、窒息、13段目の消去・落下、ちぎり、誤発火、操作列の破損を検査します。また、最適化した逆操作候補を元の全連鎖判定による実装と160盤面で照合します。

全連鎖数の統合テストでは1〜19連鎖 × 4/5色 × 余剰0/1個の76ケースを同梱設定で生成し、空盤面から構築と発火を独立検証します。CLIの追加テストでは1・5・10連鎖、奇数個の準備消去、旧設定の互換性、不正な連鎖数や余剰個数の拒否を確認します。

Python 3が見つかれば、C++とは独立したセル単位シミュレーターで76個・77個・78個、および18連鎖の生成例と全配置手順を検査します。手動でも実行できます。

```powershell
python tests/verify_output.py tests/fixtures/solutions.log --allow-extra
.\build\Release\random_19_chain.exe config.ini > generator.log
python tests/verify_output.py generator.log --allow-extra
```

## 設定

| 項目 | 意味 | 同梱値 |
| --- | --- | --- |
| `target_chain` | 生成する連鎖数。1〜19 | 19 |
| `target_success_count` | 今回新たに保存するユニークな盤面数。正の整数 | 100 |
| `initial_seed` | 探索の乱数初期値 | 20260925 |
| `color_count` | 4（通常の対戦）または5 | 4 |
| `beam_width` | 各連鎖段階で保持する盤面数の上限 | 48 |
| `restarts` | 独立探索の最大回数（各回最大1件） | 1000 |
| `candidates_per_parent` | 各親から次段階に残す候補数 | 2 |
| `min_extra_puyos` | 本体の最小個数に追加するぷよ数の下限 | 0 |
| `max_extra_puyos` | 追加するぷよ数の上限。最大 `78 - 4 * target_chain` | 0 |

### 設定ファイルの形式と各項目の詳細

`config.ini` はUTF-8（BOMあり／なし）で保存できます。`key = value` 形式で、空行と `;` / `#` 以降のコメントを無視します。`[Generator]` などのセクション見出しは読み飛ばすため、キーはファイル全体で一意にしてください。キー名は大文字と小文字を区別します。未知のキー、重複、必須項目の欠落、不正な数値はエラーです。

- **`target_chain`**: 本体の連鎖数。1〜19を指定します。奇数個の盤面の準備消去は、この連鎖数に含めません。省略時は19です。
- **`target_success_count`**: 今回の実行で新たに保存する盤面数。初期値100です。過去のファイルにあるURLは件数に含めず、重複した盤面も数えません。目標に到達した時点で終了します。
- **`initial_seed`**: 探索用乱数の初期値。0〜18446744073709551615の10進整数です。同じ実装・全設定・URL保存履歴で探索を再現できます。ゲーム内のツモを再現する乱数シードではありません。別の盤面が欲しい場合は変更してください。
- **`color_count`**: 使用する通常ぷよの色数。4または5です。4色は通常の通の対戦に対応し、5色の探索も可能です。どちらでも最初の3組は合計3色以内とします。おじゃまぷよは生成しません。
- **`beam_width`**: 各逆操作段階で保持する候補盤面数の上限。正の整数です。大きくすると多様な候補を残せますが、1試行の時間とメモリが増えます。測定した19連鎖・76個では48を採用しました。幅を増やせば出力が速くなるとは限りません。
- **`restarts`**: 独立探索の最大回数。正の整数で、初期値1000です。1試行につき新しい盤面は最大1件なので、目標件数以上の値が必要です。失敗や重複にも試行を使うため、目標件数と同じ値では通常足りません。上限に達しても保存済みURLは残ります。余剰の多い盤面や別のseedで100件に届かなければ、この値を増やしてください。
- **`candidates_per_parent`**: 各親盤面から次の段階へ引き継ぐ候補数。正の整数です。最終段階では候補をすべて検査します。初期値2は、少数の候補で短い探索を繰り返す方が速かった実測に基づきます。`beam_width` と組み合わせて調整してください。
- **`min_extra_puyos` / `max_extra_puyos`**: 最終発火直前の盤面に置く、最小個数 `4 * target_chain` より余分なぷよ数の下限／上限です。連鎖後にもこの個数が残ります。両方の省略時は0で、`0 <= min <= max <= 78 - 4 * target_chain` が必要です。等しい値なら個数を固定し、異なる値なら各試行で範囲内から選びます。準備で消す5個は含めません。

`initial_seed` 以外の正の整数項目は最大2147483647です。連鎖数・色数・余剰個数には上記の追加制約があります。設定できる範囲と、短時間で生成できる範囲は異なります。

初期設定の全項目:

```ini
[Generator]
target_chain = 19
target_success_count = 100
initial_seed = 20260925
color_count = 4
beam_width = 48
restarts = 1000
candidates_per_parent = 2
min_extra_puyos = 0
max_extra_puyos = 0
```

従来の6項目は必須です。旧設定ファイルはそのまま使えます。追加した3項目の省略時は `target_chain=19`, `min_extra_puyos=0`, `max_extra_puyos=0` です。整数で `0 <= min <= max <= 78 - 4 * target_chain` を満たす必要があります。範囲内から均等に残り個数を選んで探索しますが、各個数の成功数が均等になる保証はありません。

例：77個の19連鎖だけを探索する場合は以下を指定します。

```ini
target_chain = 19
min_extra_puyos = 1
max_extra_puyos = 1
```

18連鎖で72〜78個を許可する場合は、`target_chain=18`, `min_extra_puyos=0`, `max_extra_puyos=6` とします。18連鎖75個だけなら `min=max=3` です。

同じ実装・設定・保存履歴で探索を再現できます。保存先は**実行時の作業フォルダー**です。設定ファイルの場所は引数で指定できます。

```powershell
.\random_19_chain.exe C:\path\to\config.ini
```

試行上限に達すると生成済みURLを残して終了コード1を返します。目標達成は0、設定／入出力エラーは2です。目標に届かない場合は `restarts` を増やすかseedを変更してください。幅を増やしても単位時間当たりの成功数が上がるとは限りません。同梱値は48/2です。複数seedで有効な出力数/秒と最初・5個目までの時間を比較してください。

操作列の `L/R/D` は左・右・1段落下、`A/B` は右・左回転です。クイックターンは同じ回転を2回出力します。最後に接地・固定し、横置きはその後に分離して落下します。座標と2文字の色は**軸／子の順**です。操作列の各文字はフレーム数を指定していません。奇数個の準備消去は3手目の `setup_clear=5` で明示します。

## 探索の改善

消去の逆操作で連鎖を伸ばす方法を維持し、色を付ける前に既存ぷよの連結を1回だけ調べます。既存の4個以上の成分や追加グループと同色になる境界を先に除外し、有効候補を小さな挿入情報として保持し、ランダム選択後に使う候補だけを盤面化します。捨てる候補の列配列を確保せず、選択順と乱数の状態は変更前と一致させています。連鎖判定の作業領域は固定配列とし、成分ごとの動的確保を減らしました。候補選択はランダムを維持し、必要な盤面の多様性を保ちます。

余分なぷよは、連鎖終了時に残る指定個数の安定盤面を探索の出発点にすることで実装しています。完成盤面への後付けではないため、逆操作の「単独4個消去で元の盤面に戻る」条件を維持します。

測定条件と結果は [BENCHMARK.md](BENCHMARK.md) を参照してください。

## 生成速度の検証結果

2026-09-30、Windows x64、Visual Studio 2022 / MSVC 19.44、Release / O2で測定しました。空のURL履歴から19連鎖・76個・4色を各seedで20件生成し、起動時間と失敗した探索時間を含めています。生成プロセスは1個ずつ実行しました。待ち時間は各seedでの値の中央値です。

| 幅 / 親ごとの候補数 | seed数 | 検証済み件数 | 合計秒 | 出力/秒 | 最初の出力まで（秒） | 5個目まで（秒） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 128 / 32 | 3 | 60 | 59.29 | 1.01 | 0.30 | 5.04 |
| 32 / 2 | 6 | 120 | 47.41 | 2.53 | 0.39 | 1.79 |
| **48 / 2（採用）** | 6 | 120 | 43.31 | **2.77** | **0.47** | **1.81** |

同じ3seedに揃えると、採用した48/2は128/32の約2.49倍の出力/秒でした。最初の1件までの時間にはばらつきがあり、128/32が速いseedもあります。初期値は継続的な出力速度と5件までの待ち時間を併せて選んでいます。粗い比較では4/5色、幅4〜4096、親候補数2〜32を試しました。高い成功率だけを優先すると、大きな幅の処理時間で出力が遅くなりました。

新しい初期設定（生成目標100、試行上限1000、seed20260925）でも測定し、**100件を36.29秒・713試行で生成**しました。最初の出力は0.57秒、5個目は1.71秒で、100件すべての構築・発火を独立検証しています。[100件生成の測定データ](benchmarks/default-100-results.json)

同じ48/2で余剰個数も検査しています。各行は3seedで10件ずつ生成した実測です。

| 条件 | 検証済み件数 | 合計秒 | 出力/秒 |
| --- | ---: | ---: | ---: |
| 19連鎖・77個のみ | 30 | 15.36 | 1.95 |
| 19連鎖・78個のみ | 30 | 33.19 | 0.90 |
| 19連鎖・76〜78個 | 30 | 14.72 | 2.04 |
| 18連鎖・72〜78個 | 30 | 8.61 | 3.48 |
| 10連鎖・43個のみ | 30 | 0.45 | 66.77 |

別途、18連鎖・77個を5件（3.07秒）生成・検証し、18連鎖72〜78個すべての個数を確認しました。すべての出力で、独立したPythonシミュレーターにより空盤面からの操作経路、途中の消去、最終個数、各消去波を検証しています。速度はCPU、ビルド、seed、保存履歴、連鎖数、余剰個数で変わります。

測定の詳細と元コードとの比較は [BENCHMARK.md](BENCHMARK.md)、生データは [benchmarks/sequential-results.json](benchmarks/sequential-results.json) と [benchmarks/extra-results.json](benchmarks/extra-results.json) にあります。

再測定の例（普段のURL履歴を変更せず、一時フォルダーで実行）:

```powershell
python tools/benchmark.py build/Release/random_19_chain.exe --target 100 --restarts 1000 --seconds 180 --save-log run100.log
python tests/verify_output.py run100.log --allow-extra
python tools/tune_parameters.py build/Release/random_19_chain.exe benchmarks/refine-plan.json measurements --workers 1
```

`--seed`、`--colors`、`--beam`、`--per-parent`、`--chain`、`--min-extra`、`--extra` で条件を指定します。出力JSONには成功件数、完了試行数、経過時間、最初／5個目の時刻、打切り状態を記録します。公平な速度比較には複数seedを使い、同じPCで1プロセスずつ実行してください。
