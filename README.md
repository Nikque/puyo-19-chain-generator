# ぷよぷよ盤面ジェネレーター

[English README](README.en.md)

4色または5色で、最後の1組を置くと指定どおりに連鎖する1〜19連鎖の盤面をランダムに生成するC++20プログラムです。成功した盤面のURLを `19chain_urls.txt` に追記します。初期設定では、19連鎖・76個・4色の新しい盤面を100件生成します。

盤面処理はすべてビットボード（1列16bit × 6列を1本のSSEレジスタに入れ、3本で色を表す48バイトの盤面）で行います。同じ盤面コア（`core/`）を、今後のとこぷよ・対戦・AIでも使えるようにしてあります。

## Windows GUI

`PuyoChainGenerator.exe` で設定編集・生成中断・結果選択・6×13盤面・連鎖の再生を利用できます。CLI（`random_19_chain.exe` / `run.cmd`）も利用できます。操作、保存先、ビルド、対応範囲は [GUI_README.md](GUI_README.md) を参照してください。
GUIの盤面URLは石川ぷよ・対戦ぷよパーク・mattulwan系（pndsngミラー）から選べます（[URL_FORMATS.md](URL_FORMATS.md)）。
盤面編集、元に戻す・やり直し、編集盤面の連鎖再生と保存・読込に対応しています。通常5色に加え、おじゃま・得点・かた・鉄・壁を扱います。これらはランダム生成には含めません。

CLIのexeの直接実行でも日本語を表示できます。コンソールが接続されている場合は実行中だけ出力文字コードをUTF-8にし、終了時に元へ戻します。ファイルへリダイレクトしたログもUTF-8です。Windowsの設定パスには日本語や絵文字も使えます。URLファイルの最終行に改行がない場合も、次のURLを別の行に追記します。

## 生成される盤面の条件

出力する盤面は「最後の1組を置いた直後」の盤面です。次の条件をすべて満たします。

1. 6列×13段。どの列にも空洞がなく、14段目には何も置きません。
2. 発火すると、指定した連鎖数ちょうどの波が起き、各波は**同時消しなしの単独4個消し**です。
3. 13段目は連結・消去に参加せず、下のぷよが消えると落下します。
4. 連鎖が終わった盤面で、左から3列目・下から12段目（組ぷよの出現位置）が空いています。
5. 盤面の個数は `4 * target_chain + extra` です。`extra` は `min_extra_puyos` から `max_extra_puyos` の範囲で選び、連鎖後にその個数が残ります。
6. **最後の1組**が1つ以上あります。最後の1組とは、盤面の最上部の2個（同じ列の上2個、または隣り合う2列の最上段1個ずつ）で、次を満たすものです。
   - その2個を除いた盤面では何も消えない。
   - その2個を除いた盤面で、3列目12段目が空いている（組ぷよが出現できる）。
   - その置き方に組ぷよが届く（下の到達規則）。

最後の1組を置いた時点で3列目12段目が埋まっていても構いません（置いたぷよが連鎖で消え、4. を満たせばよい）。

盤面ごとに、最初に消える4個（発火点）と、条件6を満たす最後の1組を**すべて**出力します。

### 到達規則

組ぷよは3列目に出現します（12段目が軸、13段目が子）。列の高さだけから、次の規則で届くかどうかを判定します（[puyoai](https://github.com/puyoai/puyoai) の `PuyoController::isReachable` と同じ規則）。

- 11段以下の列は通れます。
- 13段の列（13段目にぷよがある列）は越えられません。軸ぷよは14段目に入れないためです。
- 12段の列は、軸ぷよを13段目に上げられる時だけ越えられます（壁越え）: 出現直後に2列目と4列目がともに12段以上（クイックターン）、直前の列がちょうど11段（床蹴り）、または12段の列から1列空きを挟んだ次の12段の列。
- 縦置きは11段以下の列にだけ置きます（14段目にぷよを残さないため）。

v0.3.0までの移動モデル（壁蹴り・床蹴り・クイックターンを幅優先探索、落下なし）が許す置き方は、この規則が許す置き方をすべて含みます。全ての高さの組合せ（645万通り）で確認済みで、差は「浮いたまま低い列の上を横切る」移動だけです（`tools/compare_reach.cpp`）。

### 保証しないこと

- **空盤面からその盤面を組み上げる手順は出力しません**（v0.3.0までは出力していました）。保証するのは「最後の1組を置けば発火する」ことだけで、そこまでの積み方は利用者に任せます。
- フレーム単位の自動落下、接地時間、入力受付時間、機種差はモデル化していません。特定ゲームの配ぷよ列との照合は行いません。おじゃまぷよは生成しません。

### 各盤面は独立に生成します

1回の探索（試行）は、試行番号ごとに独立した乱数系列で、連鎖後に残る盤面から始めます。1回の探索から保存する盤面は最大1つです。見つかった盤面を少し変えて似た盤面を量産することはしません。過去の `19chain_urls.txt` と今回の実行中の同じURLは除外します。

## 探索の仕組み

連鎖を逆向きに伸ばします。連鎖後に残る盤面（余剰ぷよだけの、何も消えない盤面）から始め、1段ごとに「4個の組を列の途中へ差し込む」逆操作を行います。差し込んだ盤面で、(i) 差し込んだ4個以外に4個以上の連結がなく、(ii) 差し込んだ4個が周囲の同色とつながらない場合だけ採用します。すると、その盤面で消えるのは差し込んだ4個だけで、落下後は元の盤面に正確に戻ります。したがって n 回の逆操作で作った盤面は、必ず単独4個消し n 連鎖になり、最初に消えるのは最後に差し込んだ4個、連鎖後は出発点の盤面です。この性質は連鎖数・余剰個数・色数によりません。

このため、探索の内側では連鎖のシミュレーションを行いません。条件ごとの扱いは次のとおりです。

| 条件 | 探索中の判定 |
| --- | --- |
| 連鎖数・単独4個消し・発火点 | 作り方から必ず成り立つので判定しない |
| 連鎖後に3列目12段目が空 | 連鎖後の盤面は出発点そのものなので、出発点を作る時に3列目を11段までにする（余剰が11個以下なら自動的に成り立つ） |
| 14段目に置かない | 差し込み時に高さ13段以下を保つ |
| 最後の2個を除くと何も消えない | 「その2個が発火点の4個のどれかを含む」と同値。マスク演算で判定 |
| 最後の1組が出現できる・届く | 候補の組ごとに高さから判定 |

逆操作はビット演算で行います。列への差し込みは列ごとの乗算（シフト）、4個以上の連結の有無は「同色の隣があるか」の4枚のマスクから flood fill なしで判定します。候補位置は、発火点のぷよを動かす位置と列の高さに合う位置のビット集合から直接求めます。

各段階では親盤面ごとに `candidates_per_parent` 個を一様に選び、`beam_width` 個まで残します（ビーム探索）。最終段の直前だけは全ての子盤面を残します。

**保存する盤面には、上の導出に頼らず、全条件をそのまま検査します**（`verifySolution`）。さらに、C++とは独立したPythonのセル単位シミュレーター（`tests/verify_output.py`）が同じ条件を検査し、出力された「最後の1組」が条件を満たす組の全てと一致することも確認します。

試行は複数スレッドで並列に実行します。試行番号ごとに乱数系列が決まり、番号順に結果を確定するので、**同じ設定なら、スレッド数やコンパイラによらず同じ盤面を同じ順で生成します**。

## ビルドとテスト

Visual Studio 2022などのC++20コンパイラーとCMake 3.16以降を使います。x64ではSSE4.1とPOPCNTを使います（PEXT/PDEPは実行時にCPUを判定して使い分けます）。それ以外のCPU向けに64bit演算だけの実装も入っており、テストで両方を検査します。

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
cd build/Release
.\random_19_chain.exe
```

性能測定は必ず **Release** で行ってください。

| テスト | 内容 |
| --- | --- |
| `core_and_generator`（SSE版・移植版） | 乱数盤面（空洞・おじゃま・13段目を含む）でビットボードの消去・落下・得点をセル単位の参照実装と照合。逆操作の候補を v0.3.0 の全連鎖判定実装（`tests/reference/v030_engine.h`）と照合。最後の1組の近道判定を定義どおりの判定と照合。到達規則の固定例と v0.3.0 移動モデルとの包含関係。乱数の固定値。PEXTなしの落下 |
| `all_chain_lengths` | 1〜19連鎖 × 4/5色 × 余剰（0個・1個・上限・0〜上限）の152設定で生成し、全盤面を独立検証 |
| `config_and_generation_integration` | 設定の互換性・不正値の拒否・履歴追記・重複除外・スレッド数によらず同じ出力 |
| `independent_output_verification` | 同梱の生成例を独立検証 |
| GUI関連 | 設定・保存形式・再生・編集・特殊ぷよ・実ウィンドウでの統合検証と、その成果物の独立検証 |

```powershell
python tests/verify_output.py tests/fixtures/solutions.log --allow-extra
.\build\Release\random_19_chain.exe config.ini > generator.log
python tests/verify_output.py generator.log --allow-extra
```

## 設定

| 項目 | 意味 | 同梱値 |
| --- | --- | --- |
| `target_chain` | 生成する連鎖数。1〜19 | 19 |
| `target_success_count` | 今回新たに保存するユニークな盤面数 | 100 |
| `initial_seed` | 探索の乱数初期値 | 20261004 |
| `color_count` | 4（通常の対戦）または5 | 4 |
| `beam_width` | 各連鎖段階で保持する盤面数の上限 | 48 |
| `restarts` | 独立探索の最大回数（各回最大1件） | 100000 |
| `candidates_per_parent` | 各親から次段階に残す候補数 | 2 |
| `min_extra_puyos` | 最小個数に追加するぷよ数の下限 | 0 |
| `max_extra_puyos` | 追加するぷよ数の上限。最大 `78 - 4 * target_chain` | 0 |
| `threads` | 探索スレッド数。0は自動（論理プロセッサ数の半分） | 0 |

`config.ini` はUTF-8（BOMあり／なし）で保存できます。`key = value` 形式で、空行と `;` / `#` 以降のコメントを無視します。`[Generator]` などのセクション見出しは読み飛ばします。未知のキー、重複、必須項目の欠落、不正な数値はエラーです。

- 必須は `initial_seed`, `color_count`, `beam_width`, `restarts`, `candidates_per_parent`, `target_success_count` の6項目です。省略時は `target_chain=19`, `min_extra_puyos=0`, `max_extra_puyos=0`, `threads=0` です。v0.3.0までの設定ファイルはそのまま使えます。
- `initial_seed` は0〜18446744073709551615の10進整数です。ゲーム内のツモを再現する乱数シードではありません。
- `beam_width` を大きくすると1回の探索の成功率が上がり、その分1回の時間が増えます。毎秒の生成数はほぼ変わりません。
- `candidates_per_parent` を1にすると候補が広がらず、ほとんど成功しません。
- 余剰は `0 <= min <= max <= 78 - 4 * target_chain`。等しい値なら個数を固定し、異なる値なら各試行で範囲内から選びます。奇数個の盤面もそのまま生成します。
- `initial_seed` 以外の正の整数項目は最大2147483647、`threads` は最大256です。

例：77個の19連鎖だけなら `target_chain=19`, `min_extra_puyos=1`, `max_extra_puyos=1`。18連鎖で72〜78個なら `target_chain=18`, `min_extra_puyos=0`, `max_extra_puyos=6`。

保存先は**実行時の作業フォルダー**です。設定ファイルの場所は引数で指定できます。

```powershell
.\random_19_chain.exe C:\path\to\config.ini
```

終了コード: 目標達成は0、試行上限に達した場合は1（生成済みURLは残ります）、設定／入出力エラーは2です。

### 出力の読み方

```
trigger cells (x from left, y from bottom, 1-based): (3,9) (3,10) (3,11) (3,12)
last pair options (V vertical, H horizontal): V(3,12)(3,13)
```

`trigger cells` は最初に消える4個、`last pair options` は最後に置く1組の候補です（縦置き V、横置き H。どれか1つを最後に置くと発火します）。座標は左からの列・下からの段で、1始まりです。

## 生成速度

2026-10-04、Windows 11 x64、Ryzen 9 9950X、Visual Studio 2022、Release。空のURL履歴から seed 20261004・幅48・候補2 で生成し、起動時間と失敗した探索を含みます。同じPCで他の処理も動いていたため、数値は目安です。

| 条件 | v0.3.0（20件） | 新・1スレッド（2000件） | 新・16スレッド（2000件） |
| --- | ---: | ---: | ---: |
| 19連鎖・76個・4色 | 3.81秒（5.2件/秒） | 4.83秒（414件/秒） | 0.41秒 |
| 19連鎖・77個・4色 | 8.65秒（2.3件/秒） | 6.78秒（295件/秒） | 0.81秒 |
| 19連鎖・78個・4色 | 17.54秒（1.1件/秒） | 12.67秒（158件/秒） | 1.07秒 |
| 18連鎖・72〜78個・4色 | 2.87秒（7.0件/秒） | 3.26秒（613件/秒） | 0.57秒 |
| 10連鎖・40個・4色 | 0.33秒 | 1.05秒（1900件/秒） | 0.48秒 |
| 19連鎖・76個・5色 | 5.51秒（3.6件/秒） | 5.66秒（353件/秒） | 0.71秒 |

19連鎖・76個を16スレッドで20000件生成すると3.66秒（約5,500件/秒）でした。v0.3.0 は空盤面からの構築手順も探していたので、同じ仕事の比較ではありません。詳細は [BENCHMARK.md](BENCHMARK.md) を参照してください。

```powershell
python tools/benchmark.py build/Release/random_19_chain.exe --target 2000 --restarts 100000 --threads 1 --save-log run.log
python tests/verify_output.py run.log --allow-extra
```
